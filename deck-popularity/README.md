# 卡牌组合热门程度竞猜

打开上一级 `deckPopularity.html` 即可离线游玩；主页也有入口。

## 当前规则

- 初始 5 血。答对 +1 分并进入下一轮；答错扣 1 血，揭晓答案后重新生成当前轮题目，分数、轮次和难度不变。血量归零才结算。
- 每个选项可包含不同数量的卡，也可只有单卡。普通模式每种卡只要求至少携带一张；独立的满编模式要求每种卡都携带三张，卡图标注 ×3。
- 同题各选项完全不共用卡牌，避免只有一张不同、其余都一样的比较。
- 约 90% 的题目优先让所有组包含相同种数的卡。允许双卡后的前几轮，同种数题优先双卡（70%）；通过 8 轮后优先双卡（95%），通过 18 轮后优先双卡或三卡（55% / 42%），仅少量保留全单卡题。混合长度题从中期起优先避免单卡占一半或更多；所选种数无法配出公平题目时先尝试其他多卡种数，题库受限时才逐步放宽长度偏好。
- 可以有经过核对的 0 套组合，但每题至多一个，避免多个明显无效的干扰项。
- 罕见门槛按已通过轮数降低：0–4 轮为 100 套，5–9 轮为 90 套，10–14 轮为 80 套，15–19 轮为 70 套，20–24 轮为 60 套，25–29 轮为 50 套，30 轮后保持 40 套。低于门槛才算罕见，恰好达到门槛不算。答错不会降低门槛。
- 每题至少一组达到当前门槛，避免全部都是罕见组合；通过 8 轮后优先让前两名都达到当前门槛，并优先补充非罕见干扰项。罕见门槛和答案差距分别判断，降低罕见门槛不会放宽相差至少 50 套的要求。
- 第一名数量下限按实际关卡逐步降低：第 1–8 关 500 套，第 9–12 关 400 套，第 13–18 关 300 套，第 19–30 关 250 套，第 31–50 关 200 套，第 51–70 关 150 套，第 71 关起 100 套。不再额外设置“优先数量”门槛；答错重试不降低本关下限。
- 每题至多一个 1000+，其余都是精确计数。第一名至少比第二名多 50 套，最初至少为第二名的 2.5 倍，通过 4 轮后至少 2 倍、8 轮后至少 1.6 倍、12 轮后至少 1.4 倍、18 轮后至少 4/3 倍、24 轮后至少 1.25 倍；例如后期允许 400 对 300，不允许 360 对 355。截断值只按下界 1001 验证；跨职业后优先使用精确计数的赢家来控制接近程度。
- 点击卡图查看详情；数字键 1–9 可选择前九组，其余组点击选择；结算可查看全部尝试记录。
- 手机窄屏采用两列紧凑布局，血量和分数固定在顶部，提交/下一轮固定在底部，题目和答案在中间独立滚动。先选择组合，可修改选择，再用底部按钮提交；桌面端仍点击选项直接提交。扣血时该颗心短暂裂成两半并淡出，系统开启减少动态效果时不播放动画。
- 揭晓答案后，每组下方显示最多 3 套符合条件的卡组链接，结算记录也保留这些链接。0 套组合显示暂无卡组；链接在新标签页打开官网详情，需要联网。

## 难度

| 已通过轮数（得分） | 选项数 | 每组卡牌上限 | 职业范围 |
|---|---:|---:|---|
| 0–3 | 2 | 1 | 同职业 |
| 4–7 | 2 | 2 | 同职业 |
| 8–11 | 3 | 2 | 同职业 |
| 12–17 | 3 | 2 | 可以跨职业 |
| 18–23 | 3 | 3 | 可以跨职业 |
| 24–29 | 3 | 3 | 可以跨职业；数量提示只显示最大、最小值 |
| 30–39 | 4 | 3 | 可以跨职业；同上 |
| 40–49 | 5 | 3 | 可以跨职业；同上 |
| 此后每通过 10 轮 | 再增加 1 组 | 3 | 可以跨职业 |

两种模式共用这些节点，在通过对应轮后生效，例如第 5 轮开始允许双卡、第 13 轮开始允许跨职业。玩家不选择职业，前 12 轮每轮随机抽取同职业组合；跨职业比较时，每个组合内部仍为同职业卡牌，并逐组选明职业。每次只提高选项数或组合长度上限；单卡和不同长度选项始终可出现。四卡数据不随网页题库加载。网页上方不显示“开始接近”等难度提示。最高分沿用现有存储键。

作答前，所有选项框上方单独显示本题数量提示，从大到小排列，不对应具体选项。前 24 轮显示全部数量；第 25 轮起只显示最大值和最小值，中间位置用「？」代替。各组合在作答前仍不显示对应数量，选择后揭晓全部实际数量。答错重试仍采用本轮的提示规则，结算中的答题记录保留完整数量。

前两名的优先数量比随通过轮数缩小：0–3 轮为 3–6 倍，4–7 轮为 2.5–4.5 倍，8–11 轮为 2–3.5 倍，12–17 轮为 1.6–2.8 倍，18–23 轮为 1.4–2 倍，24–29 轮为 1.3–1.9 倍，30–39 轮为 1.25–1.8 倍，40–49 轮为 1.25–1.65 倍，50 轮后为 1.25–1.5 倍。先选一个符合目标范围的第二名，再补齐其余选项。职业题库或卡牌不重复限制下，优先范围可以放宽，50 套和本阶段最低比例的限制始终保留。

## 数据

使用官网 `POST https://shadowverse-wb.com/web/DeckSearch/index`，`battle_format: 1`，记录 `count`、`is_limit` 和查询时间。统计对象是有记录的公开指定卡组，不代表天梯使用率。不同发布记录分别计数。

对于未超限的基础查询，采集器分页收齐全部卡组，并读取 `deck_card_num`。`evidence.json` 保存其卡牌数量，不含玩家姓名。满足更严格的卡牌组合，必然也满足基础条件，因此可以在这个完整集合中精确统计，包括 0 套；不是从少量样本中推断全站为 0。

`data.js` 只包含当前可用的一、二、三卡组合，`images/` 为本地 WebP。历史多张同卡及四卡资料仅保留在采集缓存中，不随网页题库加载。数量是采集快照，网站在采集期间的变化不具备跨请求事务一致性。

## 更新与验证

### 满编模式：由 BAT 自动采集

开局可选普通模式或满编模式，题库和最高分分别保存。难度表中的卡牌上限指不同卡的种数：满编模式的双卡组合是两种卡各三张。初始血量、答错重试和答案差距规则保持一致。

首次使用，请双击网页同目录的 `fetch-full-playset.bat`。需要 Node.js 18+ 和网络；不需要 ImageMagick。程序使用现有卡牌资料和本地卡图，自动采集满编统计，成功后刷新网页即可选择满编模式。满编题库尚未生成时隐藏模式选择，默认只玩普通模式；题库生成后刷新网页，自动显示模式选择。

默认目标为至少 **6,000 个组合**，其中至少 4,500 个非零组合；每职业至少有 8 个非零单卡、100 个非零双卡、200 个非零三卡组合，并检查各职业早期题目及后期跨职业题目能否满足差距和卡牌不重复要求。数量达标但无法公平出题时，仍继续收集。可在命令行提高目标：`fetch-full-playset.bat --target 10000`。

官网重复提交卡牌 ID 不能可靠筛选三张。采集器对未超限的查询分页收齐卡组，再逐套检查 `deck_card_num`，只有组合内每一种卡都带三张才计入。所有满编计数和示例都来自完整证据集合；超限查询会跳过，不使用不完整样本推算。0 套同样经过完整核对。

首次采集可能较久，自动限速、重试、保存进度；中断或失败后重新运行同一个 BAT 即可续跑。执行 BAT 时会复用普通模式缓存里已收齐的证据，普通题库及缓存不会改写。复用的旧快照不会自动刷新，统计时间范围会显示在网页“数据与统计口径”内。官网在采集期间可能发生变化，检测到数量变化或缺页就停止该次采集，保留进度。

新缓存保存为 `.cache/full-snapshot.json`，通过数量、出题和证据检查后才替换 `full-data.js`，另存 `full-evidence.json` 与 `full-report.json`。如果现有卡牌的未超限查询全部用尽仍不足，程序会明确报错并保留缓存，不发布不足的题库。项目初始仅提供空的 `full-data.js` 占位文件，需要用户运行 BAT 后生成真实数据。

离线测试（使用模拟 API，不采集数据）：`node deck-popularity/test-full.cjs`。

### 普通模式

只补双卡组合（每批每职业最多新增 100 组，合计最多 700 组；中断后去掉 `--new` 从原批次继续）：

```sh
node deck-popularity/expand-pairs.cjs --new
node deck-popularity/test.cjs
```

双卡批次覆盖不同卡牌及不同常见程度的真实构筑；按官网实际查询结果保存计数与示例，完成部分会定期写入题库。

扩大当前规则的组合库（补齐新发现的单卡，完整收集未超限的单卡查询，再统计双卡、三卡组合，并额外独立查询更多不同构筑的组合）：

```sh
node deck-popularity/expand.cjs
node deck-popularity/expand-direct.cjs
node deck-popularity/examples.cjs --collect
node deck-popularity/test.cjs
```

`expand.cjs` 调用 `expand-small.cjs`，使用缓存断点续跑。新增单卡完整查询中，非零的双卡、三卡派生结果全部保留，每个基础集合至多新增 25 个已核对的零结果。`expand-direct.cjs` 根据真实构筑挑选额外候选，再逐一向官网查询计数，同时保存卡组示例；本地出现频率只用于选候选，绝不当作官网计数。出题索引共享按计数排序的集合，避免组合库扩大后按所有组合两两预计算造成内存膨胀。

完整刷新基础数据需要 Node.js 18+、ImageMagick 及网络：

```sh
node deck-popularity/collect.cjs --fresh
node deck-popularity/collect-presence.cjs
node deck-popularity/expand.cjs
node deck-popularity/expand-direct.cjs
node deck-popularity/examples.cjs --collect
node deck-popularity/test.cjs
```

`collect-presence.cjs` 生成较小的基础组合库；完整刷新时继续执行 `expand.cjs`，保留扩充后的组合，再补齐卡组示例。已有缓存的扩充命令会复用查询快照，不会重新请求所有旧计数。

`examples.cjs` 从完整卡组缓存匹配示例；带 `--collect` 时还会查询官网，补充不足的独立查询示例。公开卡组引用只保存格式、用户 ID 和卡组 ID，不保存玩家姓名。此步骤不改变题库计数。

仅游玩不需要这些工具。采集失败可利用 `.cache/` 断点续跑；官网请求按固定间隔限速并退避重试，独立详情请求可重叠等待响应。更新完成并通过验证后再替换线上文件。

自动检查会重新核对派生计数、各职业各档题目、卡牌不重复、数量差距、唯一答案、5 血及答错重试的轮次。卡图与卡牌内容版权归 Cygames 所有。
