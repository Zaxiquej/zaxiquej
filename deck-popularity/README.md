# 卡组合理性竞猜

打开上一级 `deckPopularity.html` 即可离线游玩；主页也有入口。

## 当前规则

- 初始 5 血。答对 +1 分并进入下一轮；答错扣 1 血，揭晓答案后重新生成当前轮题目，分数、轮次和难度不变。血量归零才结算。
- 每个选项可包含不同数量的卡，也可只有单卡。每种卡只要求至少携带一张，暂不出现 ×2、×3。
- 同题各选项完全不共用卡牌，避免只有一张不同、其余都一样的比较。
- 可以有经过核对的 0 套组合，但每题至多一个，避免多个明显无效的干扰项。
- 罕见门槛按已通过轮数降低：0–4 轮为 100 套，5–9 轮为 90 套，10–14 轮为 80 套，15–19 轮为 70 套，20–24 轮为 60 套，25–29 轮为 50 套，30 轮后保持 40 套。低于门槛才算罕见，恰好达到门槛不算。答错不会降低门槛。
- 每题至少一组达到当前门槛，避免全部都是罕见组合；通过 6 轮后优先让前两名都达到当前门槛，并优先补充非罕见干扰项。罕见门槛和答案差距分别判断，降低罕见门槛不会放宽相差至少 50 套的要求。
- 每题至多一个 1000+，其余都是精确计数。第一名至少比第二名多 50 套，早期至少多 50%，后期逐步放宽到至少多 25%；例如后期允许 400 对 300，不允许 360 对 355。截断值只按下界 1001 验证；跨职业后优先使用精确计数的赢家来控制接近程度。
- 点击卡图查看详情；数字键 1–9 可选择前九组，其余组点击选择；结算可查看全部尝试记录。
- 揭晓答案后，每组下方显示最多 3 套符合条件的卡组链接，结算记录也保留这些链接。0 套组合显示暂无卡组；链接在新标签页打开官网详情，需要联网。

## 难度

| 已通过轮数（得分） | 选项数 | 每组卡牌上限 | 职业范围 |
|---|---:|---:|---|
| 0–2 | 2 | 1 | 同职业 |
| 3–5 | 2 | 2 | 同职业 |
| 6–9 | 3 | 2 | 同职业 |
| 10–14 | 3 | 2 | 可以跨职业 |
| 15–19 | 3 | 3 | 可以跨职业 |
| 20–29 | 4 | 3 | 可以跨职业 |
| 30–39 | 5 | 3 | 可以跨职业 |
| 40–49 | 6 | 3 | 可以跨职业 |
| 此后每通过 10 轮 | 再增加 1 组 | 3 | 可以跨职业 |

节点在通过对应轮后生效，例如第 4 轮开始允许双卡、第 11 轮开始允许跨职业。玩家不选择职业，前 10 轮每轮随机抽取同职业组合；跨职业比较时，每个组合内部仍为同职业卡牌，并逐组选明职业。每次只提高选项数或组合长度上限；单卡和不同长度选项始终可出现。四卡数据不随网页题库加载。网页上方不显示“开始接近”等难度提示。最高分沿用当前随机职业模式的存储键。

前两名的优先数量比随通过轮数缩小：0–5 轮为 2–4 倍，6–9 轮为 1.8–3 倍，10–14 轮为 1.5–2.5 倍，15–19 轮为 1.4–2 倍，20–29 轮为 1.25–1.8 倍，30–39 轮为 1.25–1.65 倍，40 轮后为 1.25–1.5 倍。先选一个符合目标范围的第二名，再补齐其余选项。职业题库或卡牌不重复限制下，优先范围可以放宽，50 套和本阶段最低比例的限制始终保留。

## 数据

使用官网 `POST https://shadowverse-wb.com/web/DeckSearch/index`，`battle_format: 1`，记录 `count`、`is_limit` 和查询时间。统计对象是有记录的公开指定卡组，不代表天梯使用率。不同发布记录分别计数。

对于未超限的基础查询，采集器分页收齐全部卡组，并读取 `deck_card_num`。`evidence.json` 保存其卡牌数量，不含玩家姓名。满足更严格的卡牌组合，必然也满足基础条件，因此可以在这个完整集合中精确统计，包括 0 套；不是从少量样本中推断全站为 0。

`data.js` 只包含当前可用的一、二、三卡组合，`images/` 为本地 WebP。历史多张同卡及四卡资料仅保留在采集缓存中，不随网页题库加载。数量是采集快照，网站在采集期间的变化不具备跨请求事务一致性。

## 更新与验证

只补双卡组合（每批每职业最多新增 100 组，合计最多 700 组；中断后去掉 `--new` 从原批次继续）：

```sh
node deck-popularity/expand-pairs.cjs --new
node deck-popularity/test.cjs
```

双卡批次覆盖不同卡牌及不同常见程度的真实构筑；按官网实际查询结果保存计数与示例，完成部分会定期写入题库。

扩大当前规则的组合库（补齐新发现的单卡，完整收集未超限的单卡查询，再统计双卡、三卡组合，并额外独立查询更多不同构筑的组合）：

```sh
node deck-popularity/expand.cjs
node deck-popularity/expand-direct.cjs
node deck-popularity/examples.cjs --collect
node deck-popularity/test.cjs
```

`expand.cjs` 调用 `expand-small.cjs`，使用缓存断点续跑。新增单卡完整查询中，非零的双卡、三卡派生结果全部保留，每个基础集合至多新增 25 个已核对的零结果。`expand-direct.cjs` 根据真实构筑挑选额外候选，再逐一向官网查询计数，同时保存卡组示例；本地出现频率只用于选候选，绝不当作官网计数。出题索引共享按计数排序的集合，避免组合库扩大后按所有组合两两预计算造成内存膨胀。

完整刷新基础数据需要 Node.js 18+、ImageMagick 及网络：

```sh
node deck-popularity/collect.cjs --fresh
node deck-popularity/collect-presence.cjs
node deck-popularity/expand.cjs
node deck-popularity/expand-direct.cjs
node deck-popularity/examples.cjs --collect
node deck-popularity/test.cjs
```

`collect-presence.cjs` 生成较小的基础组合库；完整刷新时继续执行 `expand.cjs`，保留扩充后的组合，再补齐卡组示例。已有缓存的扩充命令会复用查询快照，不会重新请求所有旧计数。

`examples.cjs` 从完整卡组缓存匹配示例；带 `--collect` 时还会查询官网，补充不足的独立查询示例。公开卡组引用只保存格式、用户 ID 和卡组 ID，不保存玩家姓名。此步骤不改变题库计数。

仅游玩不需要这些工具。采集失败可利用 `.cache/` 断点续跑；官网请求按固定间隔限速并退避重试，独立详情请求可重叠等待响应。更新完成并通过验证后再替换线上文件。

自动检查会重新核对派生计数、各职业各档题目、卡牌不重复、数量差距、唯一答案、5 血及答错重试的轮次。卡图与卡牌内容版权归 Cygames 所有。
